# 地图史地依据

本项目是 60×60 的策略抽象图，不是测绘地图。底图来自 `game/data/map/00_bit.bmp`：将 30×30 单色像素逐格放大为 60×60，黑色像素作为陆地、白色像素作为水域；原有城池与县治坐标按新网格等比例迁移，并贴合陆地。地点位置表达相对关系，不能用于现代导航。

## 地貌原则

- 中国地势采用西高东低的三级阶梯框架。青藏高原作为第一阶梯；塔里木盆地、黄土高原、云贵高原和四川盆地属于第二阶梯。依据：[中国地理概况（中国政府网）](https://www.locpg.gov.cn/zggq/2014-01/04/c_125956300.htm)。
- 西北保留河西走廊、祁连山过渡带和黄土高原；天山及塔里木盆地大部在当前取景范围之外。
- 西南保留青藏高原东缘、四川盆地、秦岭—大巴山、横断山和云贵高原；高原西南腹地被裁减。
- 地形交界使用混合带，避免按行政边界突然切换地貌。

## 城市与战略节点

城市采用东汉末年至三国时期常见郡治或重要据点。北方增加乐浪、蓟、上党、河内、临淄和琅琊；中原与淮徐增加彭城、小沛、汝南、广陵和合肥；西部增加陇西、阆中、巴东和涪陵；东南与岭南增加会稽、豫章、建安、交趾、苍梧和番禺。原有75个战略据点之上，接入105个郡治城市节点（同址节点复用），当前共158个可操作城市与关津据点。

节点位置优先表达道路关系和区域层次：辽东经襄平连接幽燕，太行山两侧通过上党与河内衔接河北和洛阳，徐州内部形成琅琊—下邳—彭城—小沛网络，淮南与江东经合肥、广陵、濡须口相连，益州增加汉中—阆中和巴东—夷陵两条方向，东南沿海及岭南则形成会稽—建安—番禺与荆南—苍梧—交趾路线。

关隘采用历史存在且在汉末三国交通中有战略意义的节点：

- 潼关、函谷关、虎牢关、武关：关中、洛阳和南阳方向的重要通道。
- 阳平关：汉中西北门户。
- 剑阁：蜀道关隘，三国时期由诸葛亮经营剑阁道与关防。
- 武关：关中通向南阳盆地的通道。

渡口采用官渡战役及黄河交通相关节点：

- 白马津、延津、濡须口：官渡战役及长江—淮水交通相关渡津。
- 孟津：洛阳以北的黄河古渡。

历史核对入口：[《三国志》卷一相关记载汇总](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B701)、[中国历史地图集基础上整理的三国城市关隘地图说明](https://www.ageeye.cn/map/151/)、[陕西地方志中的阳平关资料](https://dfz.shaanxi.gov.cn/zslm/fzzlk/sxjz/hzs_16205/201706/P020240923600372937321.pdf)。

## 郡国与治所名录

`game/data/history/administrative_divisions.json` 的 `commandery_seats_140` 列出105个郡国及其治所，按司隶和十二州分组；王国和属国仍各自标明，避免一概叫作“郡”。此数采用东汉行政区划较稳定时期的标准口径，并非献帝末年固定总数。史料依据为[《续汉书·郡国志》](https://zh.wikisource.org/zh-hans/%E7%BA%8C%E6%BC%A2%E6%9B%B8/%E9%83%A1%E5%9C%8B%E5%BF%97)（各郡国所列首县即其治所）及[《后汉书·百官志》](https://zh.wikisource.org/zh-hans/%E5%BE%8C%E6%BC%A2%E6%9B%B8/%E5%8D%B7118)的分州郡国统计。汉末地方增置、改名、废并频繁，相关沿革不应倒填到这份基准名录。

105个郡国治所均已对应可点选、可任命、可驻军和可占领的游戏城市节点；同址且能对应的旧据点复用，其余治所新建城市，当前共158个城市/关津据点。每个郡治节点都有唯一网格、势力归属和城市连接，点击即可打开该城管理。新增节点的城市人口、守军与资源是战略尺度的游戏估值，不是史料原数。

治所坐标载入60×60地图：同址节点使用既有网格，其余治所按历史地名和相对方位校准，并标记坐标质量。部分位置是战略网格估点，并非经纬度测绘。地图以治所生成州、郡国栅格；线路仍是受史地约束的战略抽象。

郡治城市控制随剧本变化：同址复用的城市采用剧本原有势力；新增节点沿城市连接继承上游节点势力，中立连接点仍保持中立，因此是战略级控制推定，不表示每郡均有独立史料记载的精确边界。切换剧本时会按剧本重算。

## 道路网络

- 道路几何持久化在 `game/data/map/central_plains.json` 的 `roads` 字段；当前绘制48段历史走廊主干，不再将每座城市互相连成网。105个郡治节点均接入游戏城市连接图，新增节点各有一条区域连接供驻军行军；这类郡县级连接不全部绘制在地图，避免重新铺满支路。可用 `node tools/build-road-network.mjs` 重建可视主干。
- 可视路线选取洛阳—长安、河内—河北、幽燕—辽东、青齐—徐州、南阳—荆襄、汉中—蜀中、淮泗—江东等走廊，参考《续汉书·郡国志》的治所方位、史籍中的关津战事与古道路地理研究；它们是战略层级的通道表达，不声称逐段还原汉代官方驿路。游戏城市连接图比可视主干更完整。
- 路线逐格寻路，优先平原、草地与盆地，增加山地、沼泽、沙地和水系穿越代价；相邻行政区域只增加轻微代价，不把州郡边界当作不可逾越的墙。
- 秦岭—蜀道在史料与研究中呈多条通道，而非一条笔直大道；本游戏以关隘、地形和治所关系表现走廊，60×60 网格只作战略尺度推演，不能视作考古测绘复原。可参阅[秦蜀古道研究综述](https://www.nature.com/articles/s40494-024-01155-y)与[秦岭蜀道地理信息项目](https://qinshuroads.org/)。

## 人口与城市资源

人口来源统一保存在 `game/data/history/commandery_population.json`，覆盖105个郡国；城市资源配置由该表派生，不能再给新治所写入无来源的空口数。优先采用《后汉书·郡国志》的郡国户口基准；酒泉、郁林和交趾口数缺载时采用《汉书·地理志》元始二年（2）的前期基准，辽东原文户口比例存疑，仍沿用前期基准。四者都明确标为2年，不能当作140年或剧本年份的人口。原始入口：[郡国一](https://zh.wikisource.org/zh-hans/後漢書/卷109)、[郡国二](https://zh.wikisource.org/zh-hans/後漢書/卷110)、[郡国三](https://zh.wikisource.org/zh-hans/後漢書/卷111)、[郡国四](https://zh.wikisource.org/zh-hans/後漢書/卷112)、[郡国五](https://zh.wikisource.org/zh-hans/後漢書/卷113)、[汉书·地理志](https://zh.wikisource.org/zh-hans/漢書/卷028)。

沛国原文口数为251393，采用口字后脱百字的1251393校勘值，单列 `emended` 标记及[校勘研究](https://www.cuhk.edu.hk/ics/journal/articles/v16p017.pdf)，不冒充原文直接记数。陈国、永昌等原文户口比例亦有争议，保留底本口数并记录说明，不按想象调整。辽东属国原文未载独立户口，标记 `unrecorded`；保留其已有游戏城邑估值，不复制辽东郡总口数。当前99项为原文基准，1项为校勘值，4项为前期基准，1项为缺载。

已纠正代郡把20123户误作人口的问题，口数为126188；魏郡口数为695606。京兆尹285574、左冯翊145195、右扶风93091分别登记，不再把三辅合计523860当作京兆尹。`勃海郡`统一为`渤海郡`；旧县表的`京兆尹及三辅`按所列京兆县治归回京兆尹，县治坐标与ID不变。县级数值按既有权重重新分配并保证整郡合计守恒；这仍是战略县治估算，并非史籍中逐县实测人口。

史籍记载的是整个郡国人口，不能直接当作单城人口；同一郡内还可能存在多个游戏节点。游戏因此同时保存两组概念：

- “史籍基准”记录郡国、统计年份和整郡口数，用于说明资源排序依据。
- “战时编户估算”将整郡人口按郡治地位、节点规模和周边控制范围分配，并考虑汉末战乱造成的户籍流失。
- 新增郡治的200年基础城邑估值为「郡级人口基准 × 0.32户籍保留率 × 0.12城邑份额 ÷ 同郡城市节点数」，按500人取整、下限1000；统计缺载时保留原有游戏估值。城邑份额与保留率均为可校准的游戏参数，不是史籍比例。原有战略节点保留平衡值，再统一应用各剧本倍率。现有县域模拟覆盖51组战略郡域、253个县治，不声称补齐了汉代1180县的全部县级户口。
- 已有战局只刷新人口参考来源，不重算实际城邑或县域人口，不撤销战争、征募与徭役造成的变化；新开局使用更新后的初始值。自定义郡名没有对应统计时不套用原郡口数。
- 190 年中原、河北和徐州人口总体高于官渡时期；洛阳尚未完全毁弃但治安恶化。200 年作为基础平衡点。208 年中原、徐州和荆州继续受战争影响，江东与益州因政权经营和相对稳定提高人口、农商与仓储。
- 农业参考平原耕作条件、河网和盆地粮产；商业参考都城、郡治、运河、江海港口和交通走廊；治安、守军及地方金粮则随剧本局势变化。
- 仓储按城郭等级分为 10,000—52,000，关隘、渡口和港口另设容量，使大城、交通节点与边地小城在围城耐久上形成差别。

人口数据修改后运行 `node tools/build-population-basis.mjs` 和 `node tools/build-offline-data.mjs`；前者仅同步人口、统计名称及来源，不重布地图坐标、边界与道路。用 `node tools/build-population-basis.mjs --check` 检查派生文件一致性，并运行 `node tools/test-population-basis.mjs`、`node tools/test-city-resources.mjs` 和 `node tools/test-county-simulation.mjs`。郡治生成脚本也会自动执行人口同步，避免再次产生空基准或残留已移除节点的条目。

## 游戏抽象规则

- 城市：黑色方形节点；等级越高，节点与名称越醒目。低缩放下优先显示州治和大型城市，放大后显示全部县郡节点。
- 关隘：橙色横方节点。
- 渡口：蓝色叉形节点。
- 道路：主干道与郡县支路分层绘制，路径遵循网格连通；仍是史地约束下的战略抽象，不表示现代道路或精确古道测绘。
- 河流：蓝色网格边线，不占用地形格；对应跨河道路会增加移动消耗。
- 山脉与湖泊：作为地貌标注显示，不单独占据战略节点；太行山、秦岭、大巴山等帮助辨认道路走廊，洞庭湖、鄱阳湖、云梦泽和巢湖帮助辨认水网位置。
