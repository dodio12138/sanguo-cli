# 势力官制与方面指挥企划

目标：大势力后期不必逐城逐军下令。主公只与少数方面大员（都督、州牧、郡守）打交道：任命、下方针、下专项指令、听汇报、派遣人物；具体的调兵、运粮、募兵由大员按其能力在辖区内执行。

## 1. 现状

- 势力内部官职只有一个「从事」头衔和 0–5 品级，没有层级。
- 「军团」（`state.corps`）有负责人、所属军团与城池，只能用文字命令建，「自动执行」时每月给城池加一点农商、给军团回补给，并不真正指挥。
- 郡守托管只管本郡县邑的募兵与督查。
- 战争计划、防御计划能批量生成集结与进攻命令，但仍由主公逐条下达，占本旬命令额度。
- AI 势力的军事决策（集结、进攻、驰援、补员）已有成套逻辑，可复用给玩家的方面大员。

## 2. 官制层级

```
主公
├─ 中枢：军师（总参谋）、长史（内政总管）、司马（军务）
└─ 方面
   ├─ 都督（军区：若干州或郡，统辖区内军团）
   │   └─ 州牧／刺史（一州民政；可由都督兼领）
   │       └─ 郡守（郡治）
   │           └─ 县令（世家把持或郡守兼领，不可直接任命）
   └─ 直辖郡（不设都督的郡，郡守直接向主公汇报）
```

- 州牧、刺史优先采用汉庭所授官职；没有汉庭任命时，称「领某州事」，由势力自行委任。
- 都督是势力自设的军职，不经汉庭。
- 每个人只能担任一个方面职务，可兼一个中枢职务。

## 3. 官制图（窗口）

- 官制图沿用汉庭的树状架构，仅显示官职、任职人与上下级；不混入资源、方针和管理表单，超宽时在图内滚动。
- 点击方面节点跳入“方面”页的对应详情。
- “方面”页使用左侧可折叠隶属树与右侧详情，负责任免、改隶、方针、指令、军团与汇报，中枢任免置于页底折叠区。
- 也可在舆图上切到「方面」图层，按都督辖区着色。

## 4. 方针（长期）

每个都督或直辖郡守有一条方针，决定其自主行为：

| 方针 | 大员会做什么 |
|---|---|
| 固守 | 守军补足、修城防、不出境；有来袭时在区内驰援 |
| 屯田 | 优先农商与人口，募兵只到守城底数 |
| 进取（指定目标） | 区内集结、就粮、择机攻取目标（沿用 AI 的优势评估） |
| 听调 | 不自主出兵，只执行主公的专项指令 |

## 5. 专项指令（短期，可叠加在方针上）

| 指令 | 内容 |
|---|---|
| 协同出击 | 指定目标、集结地、发动日；可点名多位都督。到期一齐进攻，未到者记失期（同汉庭联军攻势的机制） |
| 粮草先行 | 指定前线据点与粮数、限期；大员从区内调粮、建前进粮仓 |
| 增援 | 抽调指定兵力赴另一辖区或据点 |
| 坚守待援 | 指定据点死守，区内其余部队向其靠拢 |
| 战场方略 | 区内军团统一设置撤退线、战术、携粮天数、护送等级 |
| 派遣人物 | 把人物调入辖区，由大员安排（或直接点名到某城） |

## 6. 汇报

- 每月一份（重要事件即时）：辖区兵力与存粮、方针与指令进度、威胁、请求（请粮、请兵、请人）。
- 汇报写入消息中心（重要、紧急分级）和官制图节点。
- 汇报内容受大员能力影响：智力低者对敌情的估计误差大（沿用情报估计）。

## 7. 大员的能力与风险

- 执行质量看统率、智力、政治（如集结是否及时、粮草是否算足、是否贸然出击）。
- 忠诚与野心：辖区大、兵多、忠诚低、野心高的都督可能拥兵自重（不听调、截留赋税），极端时割据。
- 命令额度：大员执行指令时下的命令走 AI 同款的直接执行，不占主公本旬命令额度。这是这个系统减负的关键。

## 8. 已定的决定（2026-10-14）

1. **层级按实际领导关系**：每个方面职位（都督、州牧／刺史、郡守）都可直属主公，或隶属另一职位；势力大小结构不同，可以是两级也可以是三级。下级辖区须在上级辖区之内。
2. **大员下令不占主公命令额度**，每条执行都写入汇报。
3. **拥兵自重先做「不听调」「截留赋税」两档**，割据以后再做。
4. **AI 势力也用这套体系**（用户 2026-10-14 改定）：AI 规划分两级——中枢定大方向（主攻方向、各方面的方针与目标、协同出击），方面大员在辖区内具体执行（集结、运粮、补员、驰援）。数据按势力分存，玩家与 AI 共用同一套执行逻辑；AI 接入放在最后一期，并以长局模拟对比改造前后。
5. **旧「军团」并入**：旧档的军团自动转为直属主公的都督府，原命令改为操作方面职位。

## 9. 分期

| 阶段 | 内容 |
|---|---|
| F1 | 官制数据与官制图窗口（只读 + 任免）；旧军团迁移 |
| F2 | 方针与大员自主执行（复用 AI 军事与内政逻辑），月度汇报 |
| F3 | 专项指令：协同出击、粮草先行、增援、坚守待援、战场方略、派遣人物 |
| F4 | 能力影响与拥兵自重；长局校准 |
| F5 | AI 势力接入：中枢按战略形势设方面与方针、下协同出击，方面执行取代逐军决策；长局对比 |

## 10. 实施记录

- **2026-10-14 F1–F5 首版**：`js/core/engine/command.js`（官制数据、任免、方针、专项指令、协同出击、月报、拥兵自重、旧军团迁移、AI 中枢），`js/ui/command-ui.js`（「幕府」窗口：官制图、方面、汇报三页），开始菜单「幕府」。由 `test-force-command` 把关。
  - 方面职位：都督（任意州、郡组合）、州牧／刺史（一州；汉庭授官者显示州牧或刺史，否则称领州事）、郡守（一郡，兼该郡治太守）。辖区按州郡划定，随攻守增减城池；城归最深一级职位；下级辖区须在上级之内，同一上级之下不重叠。
  - 执行每旬一次，大员迟速看统率（司马统率略增）：固守、屯田按前线四倍、腹地二倍或一倍半守城底数设守军目标；区内据点遭围或来袭时派就近空闲军团驰援；进取先在离目标最近的辖内据点集结，战力比达到 0.45 + 智力 × 0.0025 再出击，大举出兵仍过粮秣、季节、休整的战略审核。
  - 指令：协同出击（到期在集结地及相邻处者一齐进攻，未到者失期并增拥兵度）、粮草先行（从辖内余粮城起运，玩家方面并在目标城修前进粮仓）、增援、坚守待援（守军目标 ×1.5，辖内军团靠拢）、战场方略（统一撤退线、战术、携粮、护送）、派遣人物。
  - 月报：辖区城数、守军、军团、存粮、方针与指令进度；敌情估计误差 = (100 − 智力) ÷ 250（军师智力八折亦可）；请粮、请兵、请人。
  - 拥兵度 = 兵权占全势力比例 × 野心 ÷ 5 × (100 − 忠诚) ÷ 100 × 3，宗族减半；≥ 0.35 不听调（只自保辖区），≥ 0.55 截留赋税（每月扣辖内收入两成入其治所）。召还忠诚 −10。
  - AI：六城以上的势力，按州设方面（主公所在州直辖），人选看统率、政治、忠诚，现任该州太守与主公宗族优先；每月复审，评估最优的一路（进取性强者两路）为主攻、其余边境固守、腹地屯田；新军优先在主攻方面辖内编成，主攻方面无军时由大员就地抽调超额守军编军。方面所属军团不再走逐军进攻逻辑。
  - 官渡两年推演对比改造前：袁绍 83 城（前 80）、曹操 56（56）、刘表 53（54），兵力总数高约 2.7%。
- **2026-10-14 开局史实方面与实际管辖**：`officer_postings.json` 的 `commands` 按剧本、势力预置中枢属官与方面大员，例如官渡钟繇督关中（王邑以河东太守隶之）、程昱都督兖州（刘延以东郡太守隶之），袁谭、袁熙、高干分领青幽并三州；潼关剧本诸葛亮督零陵、桂阳、长沙三郡（廖立、赵云隶之）；襄樊关羽董督荆州事（糜芳、郝普隶之）、曹仁督荆州、夏侯惇督扬州。每条附史据，在方面详情中显示。人物须在任且属本方；辖区含主公驻地、或本方在辖区内无城者跳过（`state.forceCommandSkipped`）。
  - 玩家开局的军团仍归主公直辖（预置方面不自动收编），由玩家自行划归。
  - 已在辖区内的大员留驻原地；单郡辖区以郡治、单州辖区以州治为治所。
  - AI 复审保留仍有城池的方面（不再只看首州）；新设州职位时，州内已有的郡守收为其下级，跨州方面或都督涉及该州则不再设州。六城以下的势力只维护开局方面，不新设。主攻方向只在直属主公的方面之间选，下级按边境/腹地固守或屯田。
  - 官制图：每个方面节点可展开辖郡清单（郡长官称谓、治事者、城数），直辖部分按州列出。

## 统一郡守、调整隶属与幕府舆图（2026-10-15）

用户确认：实际任命郡守即指派郡级方面，不再区分只有地方任职、却没有幕府节点的两种郡守。以下约定取代此前相应限制。

- **统一任职**：新开局与旧档载入，按每势力实际郡长官补齐唯一郡级方面；地方官署任命及已接受的太守诏令立即同步。已有方面保留ID、隶属、方针、指令、汇报和军团划归；旧档补齐不重新收编已有军队。郡尹、国相、属国都尉按民政郡职识别，郡级军事自定义职位仍独立。
- **州接纳郡**：幕府新设州级／都督方面，自动接纳同一上级之下、完全落在新辖区内的民政郡守；其他重叠仍拒绝。先设州再任郡守时，新郡级方面自动隶属最深的合适上级。民政郡职可由已有州级／都督兼领，不再因既有上级职务而缺少郡节点。
- **主动改隶**：方面详情可选新的上级，或改归主公直辖。防止自指、循环、越出上级辖区及同层重叠；郡级方面不能再下设方面。军团自身的既有方面ID、行军和专项指令不因改隶而重置。
- **真实划出**：原上级的 `scope.excludedCommanderies` 保存已划出的郡，管辖判定、军务、报表和舆图共用 `scopeContains`／`postOfCity`。重新改隶进去时恢复覆盖。普通任官重刷、月度AI复审和读档不撤销明确划出的关系。这是组织辖区，不是第二套州郡边界，不写地图格。
- **幕府窗口**：官制图使用树状架构，仅展示官职、任职人与上下级；点击方面节点跳入该方面详情。“方面”页使用左侧可折叠隶属树、右侧所选方面详情；详情分辖区与隶属、方针、专项指令、军团、汇报五页。各页独立保留滚动位置，中枢任免放在方面页折叠区；窄窗上下排列，沿用现有桌面窗口控制和按钮虚线反馈。
- **幕府地图**：新增“幕府”，本方直属主公的各方面着不同颜色，下级辖区描细线，上层方面描金边；悬停显示完整隶属链及方针。其他势力灰显，不提供其内部组织资料。图例可隐藏相应方面，任命、改隶和读档后刷新；组织索引在绘制前按组织内容构建，不逐格扫描全体方面。
- **结算与保存**：不改变每日AI、十日方面执行和月度汇报频率；没有可用军团的方面不扫描驰援威胁。组织补齐仅在初始化、读档和任命入口执行。新增方面月报增大存档，因此只将月报的固定字段紧凑保存为元组，标记 `reportsFormat:1`，读档还原完整对象；保留原有条数、全文及扩展字段，旧格式继续可读，不放宽存档体积上限。

验证入口为 `tools/test-command-hierarchy.mjs`，覆盖六剧本实任与唯一节点、州接纳、兼领、划出／改隶、防循环与越界、旧档幂等补齐、月报保存和地图提示。另复验现有幕府、任官、汉庭、存档、家族与地图测试。隔离Chromium真实操作验证了新设豫州接纳三郡、划出汝南、改隶回州、刷新恢复、普通／窄窗布局，以及按钮虚线和说明框；未在用户正式战局上操作。
