# AI 战略模式与势力整合方案：以官渡剧本为首个试点

2026-10-18。原始设计与问题分析，现已完成本轮规则、界面及存档接入；实际交付范围和验证见 [完整实现记录](AI_CAMPAIGN_IMPLEMENTATION.md)。下文“现状”表保留的是改动前的审查结果，不代表当前代码。时间、比例和分数是游戏参数，不是历史统计。

## 1. 目标

保持日模拟和现有行军、补给、持续战斗。让战争围绕少数战略目标展开，关键胜负能带来政治结果，减少数百县逐一围攻的清盘负担。天下可以通过军事征服、郡县归附、附庸和兼并走向统一；玩家始终能改变历史走向。

不把“降好战概率”“全军加速”“强制指定历史赢家”作为主要解决方式。

用户已确认继续设计，补充要求是边缘势力在连续败战、主要城池失陷后更容易经外交归降，剧情不锁定唯一流程。具体命令、评估公式、谈判分支、配置与验收见 [归降外交与剧情分支详细设计](AI_DIPLOMACY_RULES_SPEC.md)，配置样稿见 [JSON 示例](examples/ai-campaign-rules.example.json)。样稿已更新为实际运行字段；样稿本身不自动加载，需把相应子树写入规则或剧本文件。

第一阶段“统一战争授权与停战保护”已实现，范围、实际运行配置及验证见 [实现记录](AI_WAR_AUTHORIZATION.md)。其余机制已在后续实现中接通，保留以下设计作为需求依据；更细的条款扩展与多年平衡目标以完整实现记录中的限制说明为准。

## 2. 已核实的现状

| 代码位置 | 当前行为 | 对局势的影响 |
| --- | --- | --- |
| `js/core/engine/ai.js`：`runRivalAICore` | 无方面归属的闲置军团独立筛选附近目标，可以为进军目标临时宣战 | 势力虽有性格，却容易因局部机会不断增加敌人 |
| `js/core/engine/command.js`：`aiAssignPolicies` | 中枢已有一至两路主攻政策，但目标主要按相邻据点收益评估 | 已有集结与方面基础，可以扩充；尚未成为所有进攻的统一约束 |
| 同文件：`postAdvance` | AI 方面可为自己的目标宣战 | 只改闲置军团不足以限制多线战争，需统一授权 |
| `js/core/engine/diplomacy.js`：`worldFriendly` | 同盟、互不侵犯等参与友好判断，`truce` 未包括在内 | 停战没有保护住上述选目标、宣战路径，可能很快复战 |
| 同文件：`resolveWorldDiplomacy` | AI 战争满 `12` 个原始 turn 即满足随机议和的时间条件 | 日模拟下约为十二日，需核对旧旬口径，统一为明确天数 |
| `js/core/rule-engine.js`：外交命令 | `demand_surrender` 与 `vassalize` 都写入玩家的附庸表，需关系至少20 | 劝降未形成领土、官员、军队的整体接收；敌对双方也缺少战败求降路径 |
| `js/core/engine/diplomacy.js`：`resolveWorldVassals` | AI 间每季判断附庸，要求非交战、关系至少60、强方兵力至少三倍，排除玩家 | 战争压力很难自然转为称臣；与玩家附庸记录分离 |
| 同文件：`releaseLateVassals` | 满足决胜阶段条件时主动清空 AI 附庸 | 臣属不能稳定构成统一成果，后期重新进入战争 |
| `js/core/rule-engine.js`：`captureCity` | 已有郡治失陷后属县概率归附，受守军、敌军驻扎、围城等条件约束 | 应扩充现有机制，不重复新增另一套同类归附系统 |
| 同文件：`evaluateGameOver` | 最终胜利要求只剩一个势力；失去全部据点即删除其军队 | 附庸不算终局；后续兼并必须另建完整接收流程，不能靠现有灭亡删除逻辑处理 |
| `game/data/common/events.json` | 官渡有军议、粮道等事件，多为资源与军队属性选择 | 这些事件还没有构成主战场、失败重整、继承与招降相衔接的大战役流程 |

以上是能解释混战的机制，具体哪项在用户当前存档中贡献最大仍需该档战线和战报统计，不能将静态审查当成长期模拟结果。

## 3. 开局拆成两个独立选项

**历史倾向**：历史引导、自由演化。历史引导为每个剧本配置主要对手、战略区域、外交顾虑及条件事件；原条件消失后切换合理的替代目标。自由演化仍使用统一战略与整合机制，只取消历史目标加权。

**推进节奏**：标准、快速整合。快速整合缩短战后招抚与兼并协商周期，提高已经失去抵抗条件的地区归附意愿；不提高行军速度、不削弱正常守城、不凭日期强制换主。推荐默认组合为“历史引导＋快速整合”。

首期不做严格历史回放。若以后增加，应独立标识为回放玩法，避免把必败、必死、必分裂暗中放进一般游戏。

## 4. 势力先确定战争，再给军队分配任务

每个势力保存一份战略计划：主要对手、战争目标、主战区、次要防御区、允许进攻的对象、预备队、休整条件和近期战果。

- 普通时期一条主战线，大势力条件允许时增加一条次线。被多人进攻不禁止防卫，但不会因此自动向其他邻国扩大战争。
- 中枢、方面和无归属军团都经过同一进攻授权；方面不能因相邻县好打就自行新开国家级战争。
- 战争目标以郡治、渡口、粮仓、主力军团和敌方政治中心为主；普通县承担补给、连接和包抄价值。
- 预计可用兵力计入补给、组织度、伤员、行军距离和已经分配的任务，避免把同一支援军同时许给多个方面。
- 小势力可选择依附、守土、借道、求援；没有必须每月主动扩张的要求。主战场应持续推进，边缘安定不等于全局节奏变慢。

## 5. 军事胜负转化为政治变化

### 5.1 战争承受力与议和条件

用近期有效兵力损失、关键地区得失、断粮、核心人物被俘、盟援与战争持续时间计算承受力。避免将一次溃退的损失、俘虏和整编重复计分。胜利点数用于提出条件，不直接兑换任意城市。

可提出停战、赔粮、交还俘虏、割让指定郡县、接受附庸、整体归降。交战中的求降不要求先把敌我关系刷成正数；军事实力接近时，单靠好感不能吞并对方。

停战必须在选目标、宣战、行军进入、方面进取与世界外交各入口统一生效。毁约需明确命令、政治代价与盟友反应。

### 5.2 郡治失陷后的招抚

扩充现有属县归附机制。以最近失去的郡治、主力败退、补给孤立为触发，向受影响地区生成一轮招抚，而非每天对所有县随机判定。

候选县分别评估：实际太守／县官所属、地方家族支持、忠诚、驻军、援军是否可达、与胜方的路线、胜方安民或屠掠记录。提供三种结果：归附、观望、抵抗。

郡治失陷不能自动带走仍有完整主力、忠诚官员与安全后路的全郡。州治失陷也只扩大政治震荡范围，不能直接整州改色。先发送招抚并出现倒计时，期间原主可救援、增兵或安抚。

快速整合模式可先试招抚约7—20日；标准模式更长。均为调参起点。

### 5.3 附庸与兼并分开

| 关系 | 领土与军队 | 政治义务 | 后续 |
| --- | --- | --- | --- |
| 同盟 | 保持独立 | 约定援助或共同目标 | 可续盟、合法退出 |
| 附庸 | 保留本方旗号、地方官与军队 | 停止对宗主作战、贡赋、有限出兵、外交受约束 | 忠诚变化、争取自治、协商整合或叛离 |
| 整合中 | 按协定逐步移交管理权 | 保官、封爵、家族待遇和军权谈判 | 顺利并入、部分拒绝、谈判失败 |
| 直接归降／兼并完成 | 按接收清单移交资产和权力 | 按承诺安置原主及部属 | 形成新方面，随后可逐步改组 |

统一玩家与 AI 的臣属数据和验证逻辑；阻止自己附庸自己、循环臣属、重复贡赋及未经处理的多重宗主。宗主与附庸之间的战争、盟约、第三方战争须逐项清理或确认，不能清空所有战争当成和平。

兼并参考臣服时长、原主年龄与野心、继承危机、对宗主依赖和待遇承诺。主动整体归降可直接进入接收，不必强制先等待附庸数季。稳定整合可先试一至三季，遇到现实条件不符则继续自治。

接收清单必须覆盖：郡县及人口、城库与中央府库、军团与伤员俘虏、官员任命、家族态度、在途粮运、仓储、税款、方面上下级、朝廷官爵和地图图例。投降不采用攻城的资源损耗，不无条件补兵补粮；在外拒降军团继续存在，不能瞬移或直接删除。

### 5.4 地方家族参与选择

保留地方官、保护庄园家眷、赈济与封爵可提高谈判接受度；屠掠、杀俘和背约降低周边接受度。家族影响只覆盖其实际支系、任官和依附网络，不把家族籍贯当作控制整郡的证明。家族可促成投降，但不能替所有县和所有军队作决定。

投降接收可能保留旧太守及其方面；主公随后可改任，但撤换承诺中的职位会影响整合。让现有幕府、朝廷和家族系统参与战争结果。

## 6. 官渡试点的具体推进

| 阶段 | 曹操／袁绍 AI 的重心 | 局势如何推进 |
| --- | --- | --- |
| 徐州与黄河前线 | 曹操处理刘备与东方威胁；袁绍向南集结 | 主目标由据点与兵力状态决定，不为遥远空县开启新战争 |
| 官渡主战役 | 控制渡口、前进仓和粮道，集结主力，争取地方支持 | 袭粮成功只有在实际仓粮受损、补给断裂后才影响作战，不直接判定袁军失败 |
| 一方主力受挫 | 胜方获得追击和招抚窗口，败方撤军、守渡、收拢部众 | 前线孤县可归附，腹地并不立刻全部易主；袁绍获胜也适用同一规则 |
| 河北整合或中原震荡 | 根据胜负、继承与家族态度继续推进 | 支持袁氏诸子内争、求援、局部倒向曹操等条件分支；继承稳定则保留统一袁氏 |
| 区域霸权形成 | 评估下一个主战区、附庸与政治统一 | 不再靠逐个拔除遥远小势力的最后一县才能取得阶段成果 |

其他势力有自己的计划：刘表以荆州安全和影响南阳为重，刘璋关注益州与汉中，孙氏处理江东整合与淮南机会，西北诸势力处理联盟与关中利益。均允许因玩家行动、盟友求援和显著机会转向，不做永久禁战名单。

历史依据只用于提取结构：袁绍死后的继承竞争、曹操利用兄弟矛盾和袁谭求援，可以提供“政治分化加快领土重组”的玩法依据。参考《三国志》[袁绍传](https://zh.wikisource.org/wiki/三國志/卷06)、[郭嘉传](https://zh.wikisource.org/wiki/三國志/卷14)。这些记述不意味着官渡一胜即可即时吞并河北，玩法时间窗也不是史籍记载。

## 7. 胜利与可见进度

保留军事统一；另设可选的政治统一与剧本阶段目标。政治统一可试：本集团直辖及稳定附庸占天下人口约80%，控制关键政治中心，其他主要集团已接受停战与秩序，且维持两个季度。人口比例不能单独触发，避免一个人口大郡决定全国。

统计时按宗主集团去重，短期附庸、反叛中地区、敌军控制区不能直接算作稳定统一。玩家可在阶段胜利后继续征服。不得再以“到了后期”为由强制盟友反目或全部附庸独立。

界面显示本势力本期主要对手、战争目标、进度、敌方承受力的大致情报、待答复招抚和整合中的附庸。战报应说明为何归附、哪些地区拒绝、接收了多少兵粮人口，让玩家能理解地图变化。

## 8. 性能与保存

每日继续现有概率行动、战斗、行军和实际到期处理；战争计划通常每月复核，大败、政治中心易手、主公死亡等事件可提前触发并合并到一次复核。地方归附只评估受影响的郡和邻接地区，附庸整合按月／季结算。

共用势力有效兵力、郡县归属、驻军、粮运与路线索引；按相关事件失效缓存，不在每县循环中重新扫描全图。查询和 UI 预览不能消耗真实随机序列。

所有模式选择、战争计划、战果窗口、投降答复、接收事务与整合阶段写入存档。新功能对旧档默认关闭或显式迁移，不能加载后自动割地。一次接收具有事务编号及完成标记，防止读档重复发粮、重复接收人口或军团。

## 9. 建议实现顺序和验收

1. **战争秩序**：统一停战、宣战授权及时间口径；让现有中枢主攻约束闲置军团与方面。先让官渡主战场稳定形成。
2. **胜果扩大**：接入战争承受力、割地议和，扩充现有郡县归附。先验证打赢一场大战能结束一段战役。
3. **政治统一**：统一附庸数据，增加求降、整体接收、渐进兼并和集团胜利；移除强制晚期解附庸机制。
4. **历史引导**：在共同规则稳定后配置官渡条件阶段，再扩展其他剧本。历史与自由模式共享战争机制，不各写一套战斗。

采用多个固定种子的官渡观察局，记录六个月、一年、三年和五年的：同时交战对手数、主战区兵力占比、战争目标完成率、领土易手与反复易手比例、军事攻取／归附／兼并占比、独立集团数及模拟耗时。不能只用势力数量越少越好来调参。

首轮设计目标：主战区存在可辨认的曹袁争夺，外围不普遍同时开多线；关键战役后数周出现合理的政治响应；阶段胜利有可见进展，同时允许袁绍获胜、曹操长期受阻或玩家改写格局。具体完成日期与政治吞并占比待多种子实测后确定。

重点测试：玩家与 AI 的对等求降；停战期间军团、方面与外交均不自行宣战；强守县和在外拒降军团不被误吞；最后一县投降不删除尚待接收的军队；粮运和府库守恒；幕府、汉庭、县官及图例同步；附庸无循环；读档不重复接收；旧地图与玩家自定义地图不被改写。
