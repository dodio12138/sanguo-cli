# 《终端三国》开发设计 v0.1

界面与维护中的已知经验、防复发约定见 [项目经验与防复发约定](PROJECT_LESSONS.md)。

下一阶段战斗系统的史料分析、60 条首轮战例、量化指标与建议实施顺序见 [汉末三国战例与战斗系统下一步开发规划](BATTLE_SYSTEM_NEXT_PLAN.md)；该文档为研究与规划，尚未实现其中新增机制。

## 1. 产品方向

目标是一款以“旬”为回合单位的三国策略游戏。玩家既可通过常规界面操作，也可在命令终端用自然语言向 AI 军师下令。每旬先收集玩家与 AI 势力的命令，再统一结算，避免输入顺序带来的实时优势。

第一轮只验证视觉框架、地图交互、信息布局与数据边界；不会实现经济、战斗、外交、寻路或真正的 AI 调用。

## 2. 技术选择

- 原生 HTML、CSS、JavaScript，无构建步骤与第三方依赖。
- Canvas 绘制 60×60 汉末战略区网格地图（由用户提供的 30×30 像素底图逐像素放大两倍；同色相邻格不显示边线），DOM 承载面板和无障碍文本。
- 单一 `GameState` 作为原型状态容器，以事件方式通知 UI。
- 数据定义与存档状态分开，避免平衡数值散落在视图代码中。

以后若系统复杂度明显上升，可迁移到 TypeScript；数据目录与领域模型无需随 UI 框架重写。

- **写法**：

```js
// js/ui/app/example.js
SanguoApp.define("example",app=>{
  const {$,state,map,esc,toast}=app;          // 壳内稳定的函数与常量：顶部解构
  let page=0;                                  // 本模块私有状态
  function openExample(){ /* … */ app.openCityDetail(city); }   // 其他模块的导出、可变状态：用 app.名
  $("exampleButton").onclick=()=>openExample();                // 挂载时即执行的接线
  return {openExample};                        // 导出挂回 app，壳与其他模块可用
});
```

- **上下文 `app`**：壳在开头用 `SanguoApp.context({...})` 建立，含壳内函数（`esc`、`toast`、`submit`、`log`、`cityIntel`、`fogNumber`…）与可变状态的 getter/setter（`data`、`userSettings`、`pendingTurnBriefing`、`editorSource`…）。壳在两处挂载：开局画面模块在 `chooseCampaign()` 之前挂载，其余模块在 `state`、`map`、`forceBy` 建好之后挂载，挂载前 `Object.assign(app,{state,map,…})` 补入稳定常量；挂载后壳用 `const {…}=app` 取回自己要调用的导出。
- **约定**：
  - 新面板写成新模块，不再往壳里堆；模块内只解构「挂载时已存在且不再赋值」的名字，可变状态与跨模块函数一律 `app.名`，否则会拿到旧值或撞上暂时性死区。
  - 模块私有的可变状态放在模块内；壳要读写的状态留在壳，并在 `context` 里给 getter/setter。
  - 导出名在 `app` 上全局唯一，重名在挂载时报错。
  - 新文件要加进 `index.html`（`registry.js` 之后、`app.js` 之前），然后运行 `node tools/sync-asset-versions.mjs` 更新缓存版本。
- **测试**：做源码静态检查的测试用 `tools/app-source.mjs` 的 `appSource()` 取壳与全部模块的合并文本，不必关心代码在哪个文件。需要实际运行面板的测试（如 `test-window-navigation.mjs`）在 `vm` 中载入 `registry.js` 与相关模块，用桩对象充当 `app` 后 `SanguoApp.mount`。

## 3. 回合模型

```text
PLANNING（玩家/AI 下令）
        ↓ 锁定命令
RESOLVING（按阶段统一结算）
        ↓ 生成旬报
PLANNING（日期 + 10 天）
```

建议的结算阶段：内政 → 外交 → 调动 → 战斗 → 补给 → 事件。命令需包含 `id / issuer / type / payload / submittedTurn`；由规则层验证，不允许 AI 直接修改状态。

## 4. AI 接入边界

AI 只应获得经过筛选的可见世界状态和一组受控工具，例如：

```text
inspect_city(city_id)
inspect_army(army_id)
move_army(army_id, destination)
appoint_officer(officer_id, post)
propose_diplomacy(target_force, action)
submit_orders()
```

浏览器不保存模型密钥。后续应增加本地服务或服务端网关，由它暴露游戏 API / MCP，并将 AI 返回的工具调用转换为普通命令，进入与玩家相同的队列。所有写操作都经过权限、参数和规则校验，并生成审计日志。

## 5. 数据与 Mod 约定

参考大型策略游戏的数据布局，而不复制其格式。建议规则：

- `game/data/common/`：地形、兵种、建筑、官职等静态定义。
- `game/data/history/`：剧本、人物、势力、城市开局状态。
- `game/data/map/`：格网、州域、城市坐标和邻接关系。
- `game/localization/<language>/`：显示文本。
- `mods/<mod-id>/manifest.json`：依赖、加载顺序与替换路径。
- 同 ID 后加载覆盖先加载；数组默认整体替换，显式 patch 才做局部合并。
- 数据文件未来由加载器校验 schema 与引用完整性。

当前 `js/data/game-data.js` 是允许 `file://` 直接打开的浏览器镜像；`game/data/` 是未来正式加载源。后续可用小脚本从正式数据生成浏览器镜像。

### 数值校准（2026-09）

- 人口增长参数集中在 `game_rules.json` 的 `balance.economy`；治安 80 时当前自然增长约为每旬 0.026%，年化约 0.94%，占领期另有轻微负增长。
- 旧人口公式在治安 80 时每旬增长 0.6%，年化约 24%；长期模拟显示单城数年内出现倍增，已替换为年化约 1% 的量级。
- 军粮收获系数从规则数据读取，当前为每点农业 3.5 粮/旬；同种子 180 旬压力模拟中，至少一方粮仓低于 100 的旬数由 158 降至 14，低补给军团占比偏高的旬数由 119 降至 89。
- 20 年观察局发现围城失败门槛与 AI 发起进攻门槛冲突：AI 会以约 0.58 战力比攻城，但城墙破坏后须达到 0.65 才能破城，且围城补给每旬扣 10。现改为规则数据中的 `balance.siege.breach_ratio: 0.55`、`supply_drain_per_xun: 7`，两者均可由 mod 调整。
- 长期模拟器同时统计人口变化、单城峰值、粮仓归零与低补给军团占比；`node tools/simulate-campaign.mjs --runs 8 --turns 720` 可复跑 20 年观察局。
- 2026-09-30 全指令 QA 前的同种子 8 局 × 720 旬基线为平均存续势力 6.25、野战兵 80,474、低补给军团-旬占比 11.72%。发现残军刚达到 1,200 人便反复出战后，AI 改为至少整备至 3,000 人再参与主动行动，并加入 180/360 旬收束阈值；复测平均存续势力 5.75、野战兵 148,234、低补给占比 8.58%。全部样本仍未统一，下一轮应处理军团跨城集结和后期外交收束，避免继续单纯降低进攻阈值。

### P120（月度全局事件分日、空闲存档、野径预建与详情窗口节流，2026-10-17）

- 逐日结算（`_rolling`，由 `resolve` 包住 `resolveDay` 设置）时，原在月末一齐进行的全局月结分到固定日子：中枢 AI 每月 5 日，迟到附庸、世界外交、共同敌人与联盟 15 日，世家与家族月结 25 日（`monthlyDue`）；方面忠诚与方面汇报仍在月末，季度附庸不变。直接调用与旬制仍按月末。
- 实测 240 日：月末一日平均约 216 ms 降到 155 ms，最慢一日约 320 ms 降到 255 ms。
- 自动存档：到期后放到 `requestIdleCallback` 序列化与写入（约 150 ms 不再占当日结算），暂停与离开页面仍立即补存；Node 中无空闲回调时立即保存。
- 野径图构建按 radius 分格建城索引，候选与夹点只看附近格子；与原算法逐条一致（826 条边）。
- 城市详情、军团详情的每日刷新也改为 `SanguoApp.refreshLater`。
- 一年存档 1304→1332KB（同一推演战报、转运、军团略多），存档上限放宽到 1.4MB。
