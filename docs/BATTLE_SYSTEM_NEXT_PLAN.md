# 下一阶段战斗系统开发：汉末三国战例与机制提取

> 整理日期：2026-10-16。来源：用户要求统计分析汉末至三国的大大小小战役、战斗及流程，以提取玩法；随后要求保存为下一步开发文档。
>
> 初始状态：研究资料与开发规划，最初仅保存文档。2026-10-16 后续已实现小队逐格突击、阻击、袭扰及组织度与军事图层，见 [小队行动与军事图层](SKIRMISH_GAMEPLAY.md) 和开发记录 P105；本文其余机制仍为规划。量化建议不等于当前规则，已实现数值以代码与正式配置为准。

## 1. 目标与范围

目标：使战斗从主要比较兵力、武将及战力系数，进一步发展为双方争夺交战条件、管理风险并承担战后后果的过程。情报、行军、驻营、补给、援军、指挥和退路都应形成玩家可理解的选择。

- 时间范围：184 年黄巾起义至 280 年西晋灭吴；跨年战事保留时间范围。
- 首轮整理 60 条战事案例，兼有战役、局部战斗与同一战役中的阶段。**这不是 60 场互不重叠的战争，也不是该时期全部战斗的总数。**
- 官渡相持、白马、延津、乌巢等存在父子关系，后续建立结构化资料时必须记录所属战役，不能混加为战争总数。
- 案例流程是对记载的摘要，不是完整日程复原。兵力、伤亡、日期和细节没有可靠记录时保留不详，不根据胜负倒填。
- 以《三国志》正文、裴注引文、《后汉书》《晋书》相关记载为主要资料。裴注不同引书、后世整理及文学改写须与正文分开标记。
- 每例选一个“主机制”便于检索。这是本次设计归纳，不代表已证明该因素是历史上的唯一或首要胜因。
- 后续仍需扩充无专名的小规模袭击、边地战斗、山越及南中战事；本文不是全量战斗数据库，逐条来源定位与证据等级也仍需补齐。

## 2. 与现有开发的关系

本规划接续 [战斗与补给改造企划](WARFARE_LOGISTICS_PLAN.md)，当前已完成事项以 [开发记录](DEVELOPMENT.md) 及实际代码为准。旧企划“现状”描述的是当时的改造起点，不能作为当前版本缺陷清单。

已有可复用基础包括行军与路网、正面宽度、士气与伤员／俘虏、围城方式、野战运粮队、方面指挥、P97 实际撤退与追截、P98 军粮统一口径、P99 调粮舆图线路、P100 自动供粮网络等。**本文提出深化与衔接，不把这些基础重新列为从零开发。**

用户地图的海陆、海岸线与行政层约束继续有效；本规划不授权重建地形或重新手绘州域。

## 4. 分类统计与使用边界

| 主机制 | 案例数 | 对应的玩家问题 |
|---|---:|---|
| 后勤、持久与消耗 | 10 | 还能留多久？夺粮、断运还是撤回？ |
| 围城与工程 | 9 | 强攻、封锁、打援与劝降如何选择？ |
| 机动与增援 | 8 | 谁先到？从哪里来？到达后能否立即参战？ |
| 情报、欺骗与突袭 | 7 | 消息是否可靠？敌军是否已经准备？ |
| 天气、水火与疫病 | 7 | 环境怎样改变部署与行动？ |
| 指挥与组织 | 6 | 能否听令、按时会合、保持阵形？ |
| 地形与兵种运用 | 5 | 能展开多少人？什么兵能发挥作用？ |
| 撤退与追击 | 5 | 如何保存军队或扩大战果？ |
| 政治与后方控制 | 2 | 后方、家属和地方关系会不会使前军瓦解？ |
| 过程不详 | 1 | 不根据结果编造过程 |
| 合计 | 60 | 含同一战役的不同阶段，不是独立战争数 |

分类体现本次选样及设计关注，不是历史发生频率、因果权重或平衡参数。不能把“后勤 10 例”解释为后勤决定六分之一的战争，也不能直接换成攻击／防御加成。许多案例同时涉及多种机制，仅为检索暂取一个主标签。

初步优先方向：后勤、围城、机动与组织之间的衔接，以及撤退追击的持续后果。

## 5. 量化字段建议

以下是拟议指标，不是历史测量结果。先确认与现有字段的关系，避免重复增加含义接近的数值；量纲、上下限与公式待小型原型验证。

| 因素 | 可记录指标 | 实际影响 |
|---|---|---|
| 可战兵力 | 在册、掉队、伤病、已投入、预备队人数 | 不让全部在册兵力同时参与接战 |
| 展开能力 | 道路宽度、阵地正面、渡口通行量 | 先头可能独自承受攻击；复用既有正面宽度 |
| 行军疲劳 | 连续行军日、急行比例、休息时间 | 改变接敌准备与撤退能力 |
| 阵形完整度 | 已集结比例、队伍混杂、各部间距 | 改变协同、轮换及局部突破风险 |
| 士气 | 战意、信心、恐惧、邻部败退影响 | 改变继续抵抗、动摇与撤离判断 |
| 情报质量 | 发现程度、报告延迟、来源可信度 | 改变识破伏兵和判断援军的能力 |
| 营防戒备 | 壕沟、鹿角、警戒覆盖、夜间准备 | 改变突袭造成的混乱与恢复时间 |
| 补给接续 | 当前粮日、在途粮、道路日运量 | 决定能否持续驻扎、围城；沿用统一军粮账本 |
| 水源 | 可用性、取水通道是否受控 | 地形优势与驻扎生存条件分别判断 |
| 指挥协同 | 命令延迟、会合误差、服从与配合 | 使方面划分、授权和幕府任命参与战事 |
| 退路 | 通路数量、桥渡容量、截断程度 | 区分有序后撤、被击退、溃逃与被俘 |
| 地方支持 | 向导、守将可靠度、居民合作 | 改变行军、补给、受降与地方控制 |

必须区分：

1. **士气与组织**：愿意战斗不等于能够保持阵形；愿意抢战果的部队也可能因追抢辎重而失序。现有组织度与携粮负重有关，深化前需明确其含义与迁移，不直接叠加一个同名数值。
2. **预备队与未到部队**：前者是指挥官可选择投入的力量，后者还在路上；同属一个方面不等于自动参战。
3. **高地与生存条件**：街亭不应做成“上山必败”，而是分别结算阵地收益、水源、道路、指挥与支援。
4. **在途与现粮**：消息、预估与运输记录不能代替实际库存；继续遵守 P98—P100 的统一口径。

## 6. 拟议战事流程与决策

**确定目标 → 集结准备 → 接近与侦察 → 接敌展开 → 交战或相持 → 动摇与撤离 → 追击收拢 → 占领处置。**

不是每场战斗都强制逐项停顿。突袭、遭遇、围城与阻击应按实际条件进入相应阶段，避免大量确认窗口或要求玩家手操所有士兵。

| 阶段 | 玩家选择 | 代价与风险 |
|---|---|---|
| 确定目标 | 夺城、解围、歼敌、夺粮、掩护撤离、迁走人口 | 不同目标有不同完成标准 |
| 集结准备 | 等齐部队、先遣出发、准备军粮及工程物资 | 等待可能失去战机 |
| 接近侦察 | 搜索前方、派向导、隐蔽行军、急行 | 速度、隐蔽与安全难以兼得 |
| 接敌展开 | 抢险、结阵、退回营地、先头阻击 | 部分军队可能先承担损失 |
| 交战相持 | 试探、集中攻击、投入预备队、固守待援 | 过早投入会失去后手 |
| 动摇撤离 | 轮换、缩短战线、弃辎重、安排后卫 | 保存军队可能损失物资或地盘 |
| 追击收拢 | 全力追、轻骑追、控制渡口、停止追击 | 追得越远越容易失序与脱离支援 |
| 占领处置 | 安抚、受降、收缴军械、保护或迁移家属 | 改变后续地方控制与敌军归附 |

正面战斗取胜、任务完成与整个战役成功分别评价。攻方击败出城军却未能在粮尽前取城，可能仍需撤军；守方损失更多但坚持到援军抵达，也可能完成目标。

## 7. 四组重点机制案例

### 7.1 官渡：小行动串联与供应预期

白马受围 → 曹军佯动 → 白马解围 → 撤民与运输 → 延津追击、诱击 → 官渡相持 → 运输遭袭 → 获得乌巢情报 → 主营留守与袭粮分兵 → 袁军应对 → 崩溃与渡河撤离。

需要表达的决策：

- 解围是否直接奔向被围城市，还是佯动分散敌军？
- 主力袭粮时，主营留下多少兵？
- 收到粮仓遇袭的消息后，救粮还是继续攻敌主营，如何分兵？
- 敌军动摇后追兵、夺辎重还是控制渡口？

量化重点：粮食接续、情报时效、行军隐蔽、主营防御余量、援军抵达时间。

乌巢不能做成“粮仓被烧即删除全军”。损失消息、供应预期、部将判断、局部败退及转降应逐步作用。[《武帝纪》](https://zh.wikisource.org/wiki/三國志/卷01)记有袭粮期间救援与攻营的选择，以及张郃、高览转降等后续。

### 7.2 襄樊—江陵：前线胜利与后方瓦解

关羽围樊 → 洪水使魏援军受灾 → 扩大围困与收容俘虏 → 魏方继续增援 → 徐晃解围 → 吴方隐蔽进军 → 后方据点易手 → 家属消息进入军中 → 部队离散、退路恶化。

需要连接的系统：俘虏供养与看守、前后方兵力分配、守将可靠度、家属控制与安抚、盟友关系、撤退通路。

量化重点：后方守备缺口、俘虏负担、守将可靠度、家属安全信息、撤退通路。家属关系作用于具体军人与部队，不能只统一扣全军士气；也不使未被控制的在外族人自动受害。

资料：[《关羽传》所在卷](https://zh.wikisource.org/wiki/三國志/卷36)、[《徐晃传》所在卷](https://zh.wikisource.org/wiki/三國志/卷17)、[《吕蒙传》所在卷](https://zh.wikisource.org/wiki/三國志/卷54)。

### 7.3 兴势：守住时间与通道

敌军由山道来攻 → 判断援军不能立刻到达 → 先遣占据前沿险要 → 主力作为后拒 → 监视另一入侵路线 → 外援陆续抵达 → 攻方退出。

需要表达的决策：退守大城还是占据前沿；有限兵力如何分配主路与绕行道路；守军能否坚持到援军到达；攻方供应能否支撑继续停留。

量化重点：阻滞时间、通道容量、绕行时间、援军时间、持续供给缺口。不能只给王平一个大额守城加成代替前沿、后拒与外援的衔接。[《王平传》](https://zh.wikisource.org/wiki/三國志/卷43)

### 7.4 西陵：围城、打援与情报失效

城池叛降 → 吴军围城 → 修筑向内围困、向外拒援的阵地 → 晋军分路救援 → 分别应对 → 叛逃者泄露布防 → 陆抗夜间换防 → 援军攻向原弱点失败 → 有限追击 → 取城。

需要表达的决策：内外防线怎样分兵；能否承受其他方向的牵制；有人泄密后是否换防；追败军多远才不会让城内守军趁隙出击。

量化重点：内外防线完整度、兵力分配、布防泄露、换防时间、追击留下的空隙。这里应允许情报过时和主动反制，而非侦察一次永久看穿敌军。[《陆抗传》](https://zh.wikisource.org/wiki/三國志/卷58)

## 8. 资料量化与战损口径

### 8.1 结构化资料应保留的字段

| 项目 | 记录方式 |
|---|---|
| 条目身份 | 案例 ID、所属战役 ID、战区、阶段、条目层级；本表编号作为首轮索引 |
| 时间 | 年份范围、关键行动先后；有据才填具体日期与日数 |
| 参战方 | 势力、将领、部队职责、守军与援军分列 |
| 兵力 | 战区总兵、此次参战兵、当时已展开兵分别记录 |
| 战损 | 阵亡、负伤、被俘、失散、逃亡；不把所有“损失”当阵亡 |
| 战果 | 战术胜负、任务是否完成、是否占地、是否解除威胁分别记录 |
| 环境 | 地形、季节、水源、道路、营防、供应与天气；区分记载和推测 |
| 来源 | 书、卷、传、正文／裴注引书、段落定位、可访问链接 |
| 可信度 | 明确记载、约数、来源冲突、合理推测、不详；不详不是零 |
| 因果 | 史料直接说明与本次机制归纳分别记录；允许多标签 |

后续若做参数拟合或验证，按所属战役分组，不能把白马用于调参、乌巢用于独立验证，却声称测试了完全未见过的战役。

### 8.2 防止极端兵力叙事扭曲平衡

- 合肥八百人是张辽一次出击的精锐，不是合肥全体守军。不能据此做成“八百兵正面消灭十万兵”，再反推出几十倍名将战力。[《张辽传》](https://zh.wikisource.org/wiki/三國志/卷17)
- 官渡兵力差距在裴松之注中已有系统质疑。冲突数据应并列保留，不选最夸张比例作为公式目标。[《武帝纪》裴注](https://zh.wikisource.org/wiki/三國志/卷01)
- 有序撤退、被击退和溃逃分别处理。失散者可被收拢，伤员可康复；当场减员不等于全部死亡。追击可改变俘虏、失散与物资损失，但不能重复结算已损失人员。
- 战斗应由条件产生相似过程，不为特定将领或年份硬编码必胜。

### 8.3 历史与文学分层

火攻、诈降、疑兵可提取通用机制，但仍需满足可观察、可反制的条件。襄樊洪水首先表现为雨季、水位、驻营与舟船准备的关系，不做成关羽可随时发动的固定技能。

同一故事可能包含正文、裴注引书、后世改写及反驳，不能简单二分为“正史真／演义假”。例如《诸葛亮传》裴注保存并批评郭冲相关故事，记录其争议与出处应优先于直接拿来定战斗规则。[《诸葛亮传》](https://zh.wikisource.org/wiki/三國志/卷35)

## 9. 建议实施顺序与验收

实施前先核对实际规则与现有测试，确认每项属于已有能力深化还是新增机制；不从本文推断现有系统完全缺失。

| 阶段 | 工作 | 交付与验收方向 |
|---|---|---|
| A：战例资料化 | 补齐父子战役、段落、来源层级和不确定字段 | 60 条首轮索引可追溯；不重复统计战争数，不把不详填零 |
| B：目标与阶段 | 为现有交战引入任务目标、阶段与可解释结束原因 | 解围、阻击、夺粮、掩护撤离具有不同完成条件；战术胜负与任务结果分开 |
| C：展开与组织 | 衔接现有正面宽度、负重组织度，加入到达、展开与预备队区别 | 同总兵力下，急行、分批到达、渡河与狭路产生可解释差异；人数守恒 |
| D：撤退与追击深化 | 在 P97 基础上加入后卫、截渡、弃辎重及失散收拢 | 连续实际位置不跳转；追击有收益和风险，人员物资不重复扣算 |
| E：营地与情报 | 接入警戒、休整、隐蔽、夜袭与报告时效 | 突袭有准备条件及反制；侦察不永久全知；失败过程可解释 |
| F：围城与援军 | 内外防线、阻援、守军出击配合外援 | 攻城、守城、援军三方能相互影响；不能同一支兵同时守营与打援 |
| G：后方与指挥 | 衔接方面授权、命令时效、会合失期、守将与家属关系 | 有权限和控制范围；不因同属方面自动到场，不因后方失守统一删除前军 |
| H：环境扩展 | 在前述流程中加入天气、水火、疾病的条件作用 | 环境影响准备与选择，有时效及应对，避免无预警随机扣兵 |

若先做一组机制原型，优先 **展开与组织＋撤退追击**：它同时覆盖急行遇敌、渡河受击、狭路阻敌、夜袭混乱、局部突破和败兵收拢，并能复用道路、粮运和方面系统。该原型须与目标、阶段的最小定义配套。

不在本文确定攻击倍率、名将倍率、每日损耗或天气概率。先用少量可复现案例验证因果，再用代表性多势力长周期观察平衡，不能只以复现史实胜负为通过标准。

## 10. 性能、存档与开发边界

- 按活动范围结算：行军军团更新行军状态；围城地区更新围困、运输与援军；正在接敌的部队才细算展开、交战与追击。平静县城不每日运行整套战斗判断。
- 沿用逐日模拟与串行推进；战斗内部阶段不另开并发日循环，不使播放速度改变同一模拟日结果。
- 连续状态按需要逐日更新，命令到达、阶段变化及增援抵达采用事件驱动；天气等共享信息按地区缓存，避免每军重复全图扫描。
- UI、预估和史料展示不消耗真实随机源。玩家与 AI 经同一验证路径，不因 AI 身份跳过展开、库存或权限。
- 新字段须有旧档迁移与幂等默认值；读档不重新发粮、发兵或重复结算战损。沿用既有转运队列、位置和后勤账本，避免新增第二套库存。
- 阶段记录、统计和战报应有保留与汇总策略；复用现有存档体积约束，不放宽上限来掩盖逐日日志增长。
- 展示阶段、原因、风险与可采取的行动，不要求玩家理解内部公式或手工控制每次接战。
- 后续测试须覆盖同种子复现、人数与物资守恒、数组顺序、保存往返、暂停恢复、历史不确定案例及既有军粮／行军／围城回归。真实 UI 验收使用隔离战局，不动用户当前存档。
