# 战役战略、归降与政治整合实现记录

2026-10-18。本轮已把战争授权、战败压力、外交谈判、整体接收、附庸整合、条件分支和玩家界面接入实际日模拟。对应需求见 [总体方案](AI_HISTORICAL_CAMPAIGN_PLAN.md)；原始设计中的扩展条款不等同已实现功能，以本文为准。没有修改地形、海陆、海岸线或浏览器中的地图与存档。

## 如何使用

新开局的设置中选择战略倾向、整合节奏和战局目标，默认“历史引导＋快速整合＋政治统一”。也可选自由演化或传统规则。游戏中从汉菜单的“档案与情报 → 外交关系”进入，在原外交窗口内调整方针、授权方面开战、派使谈判、答复提案、查看附庸及发起整合。操作进入普通命令队列，随模拟日执行。

旧存档未记录战役政治设置时，默认沿用旧规则；可在外交窗口主动启用。关闭模式不会抹除已经签订的协议，待办答复和履约继续处理。阶段胜利后可选择继续游戏，转为军事统一目标。

## 已完成的规则

- **中央战争授权**：闲置军团、方面和外交自动宣战共用中枢的主攻对手与授权；救援可防卫，停战仍受保护。玩家可给直辖军团、全部或指定方面授予对指定对手、指定郡域、指定期限的开战权，也可撤销。授权不会突破有效和约。
- **战争压力**：独立战斗按战役编号去重，小战损设贡献上限，近期败绩随时间衰减；失去要地、断粮与核心人物被俘影响谈判，夺回和释放可恢复相关压力。不会把持续战斗的每一日都算成一场大败。
- **谈判闭环**：劝降、主动请求归降、附庸、商议整合与求和使用同一资格检查。可约定金钱、保留地方任官、保护家产、自治、贡赋；求和可割让实际接壤的本方据点。可接受、拒绝、反提案改为自治。交战双方无需先刷好感才能求降。
- **不强迫玩家投降**：向玩家提出的协议必须明确回复；超时失效。款项先冻结，失败、失效或取消返还。预览不消耗随机数，提交后保存随机结果；实质条款未变且局势未变时受冷却限制，避免连续点击重抽。
- **完整接收**：整体归降转移现有城池、人口、库粮、军队及伤兵、官员、运输、家族家眷归属、汉庭和幕府相关引用。接收具有编号和完成标志，重复处理不会重复增加资产。和平接收不套用攻城损耗，不把守军重置为200。
- **保留拒降残部**：符合条件、忠于旧主且有独立意志的在外军团可拒降，保留原军队和物资；无城但仍有真实军队的残部不会被自动删掉。既有野战先处理尚未结算的兵员，避免停战吞兵或重复发兵。
- **统一宗属集团**：宗主和附庸共用集团战争与停战，不能形成循环附庸，也不能绕过宗主另开国家级战争。集团允许实际行军和补给通行，使用驻地粮食会真实扣粮；停战本身不授予借道。既有战争归并到宗主，避免宗主停战后附庸旧战表继续生效。
- **稳定与整合**：按月结算贡赋、履约、忠诚与整合进度；宗主保护、保官承诺与待遇影响稳定。AI 和玩家都能商议兼并，低忠诚有条件反叛；双方可解除臣属并保留一个月交接停战。移除了“后期一律释放附庸”的旧逻辑。
- **战后招抚**：郡治失守后只对相关属县生成延时招抚。驻军、实际援军、县官忠诚、地方家族和接收方信誉影响结果，仍有完整主力的城池可抵抗。玩家拥有的县等待明确答复；接受时保留守军、地方人口和库粮。
- **条件分支**：规则可选择继续进攻、休整防卫、求援、求和、主动归降或有条件的继承分裂。分裂要求实际主公更替或死亡及地方反叛条件，分配现有军队、人口与资源，不指定人物必死或国家必败。
- **胜利进度**：军事统一、政治统一、区域霸权可选。政治统一默认要求稳定集团人口占比80%、关键据点占比60%、与其他大集团维持和平并持续180日；新附庸需稳定60日。区域目标需相比开局有实际推进，避免开局直接获胜。

## 配置与存档

主要代码是 `js/core/engine/politics.js`，通过 `RuleEngine.PARTS`、HTML 引用和测试环境加载。UI 位于 `js/ui/app/campaign-ui.js`，复用既有外交窗口、按钮及选择器，不引入另一套界面框架。

| 位置 | 内容 |
| --- | --- |
| `game/data/common/game_rules.json` → `balance.ai.war_authorization` | 主次攻方向、中枢复核与停战参数 |
| 同文件 → `balance.politics` | 归降公式、压力、谈判、附庸、招抚、胜利及通用条件图 |
| `game/data/history/scenarios/200_guandu.json` → `ai_campaign` | 官渡主要对手加权、区域目标，可覆盖通用条件图 |
| `policies.campaign`（存档） | 模式、节奏、目标、运行规则和剧本配置快照 |
| `diplomacy.politics`（存档） | 压力、提案、协议、接收、招抚、战略节点和阶段成果 |
| `diplomacy.worldVassals`（存档） | 全局宗属关系，兼容玩家旧附庸视图 |

[可复制的配置示例](examples/ai-campaign-rules.example.json) 使用实际字段；示例文件不自动加载，将相应子树写入上表真实数据文件后，通过 `node tools/build-offline-data.mjs` 同步离线数据。配置快照进入新局，外部文件改变不静默改变已有战局。

标准模式：答复10日、招抚20日、整合基期240日。快速整合：答复5日、招抚10日、整合基期120日。基期参与进度计算，不代表届时必定兼并。

条件图使用 `initial` 和 `nodes`，节点含 `id`、`choices`；选择支持 `when`、`weight`／`base_weight`、`weight_by_fact`、`intent`、`next`、`next_on_success`、`next_on_failure`。条件支持 `all/any/not`，事实比较支持 `eq/gt/gte/lt/lte`；节点支持 `cooldown_days`。一次复核最多一次节点转移，目标缺失时回退通用战略，不执行任意脚本。

可用意图为 `advance`、`regroup`、`seek_peace`、`seek_relief`、`offer_submission`、`split_succession`。目标选择器支持 `main_enemy`、`reachable_ally`、`weak_neighbor`、`credible_protector` 或 `{"force_id":"既有势力ID"}`；候选仍须满足当前接壤和外交合法性。主要事实包括 `recent_defeat_pressure`、`key_site_loss`、`war_exhaustion`、`offensive_readiness`、`military_disadvantage`、`succession_crisis`、`independence_resolve`、`year/month/elapsed_days/actor_id`。历史对手加权还可用 `target_active/target_relative_power`。

官渡的曹袁倾向只在剧本数据中双向加权；自由演化不使用这些历史加权。通用规则没有固定赢家、按日期吞并河北或固定袁绍死亡事件。其他剧本使用通用条件图与自动生成的区域目标，不声称每个剧本都已编写专属史实事件链。

新增普通命令：`offer_submission`、`negotiate_integration`、`respond_diplomacy`、`pacify_region`、`set_campaign_mode`、`authorize_war`、`end_vassalage`。已有劝降、附庸与求和在启用模式时接入新流程。

## 当前限制

本轮可操作条款不含赔粮、交换俘虏、正式汉廷封爵及分阶段逐城交割；整体接收是一次幂等事务，附庸则通过持续整合再决定是否并入。拒降主要落实到在外军团，不声称每个大族和中央集团都有独立谈判 AI。

半年多种子和全剧本短期检查验证了运行与整合链路，尚未证明一到五年的战争平衡、史实相似率或每个剧本的最佳节奏。当前版本完成本轮玩法闭环，后续数值应依据真实战局继续校准。
