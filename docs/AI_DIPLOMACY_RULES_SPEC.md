# AI 战略、归降外交与剧情分支详细设计

2026-10-18。承接 [总体方案](AI_HISTORICAL_CAMPAIGN_PLAN.md)。用户已确认：边缘弱势势力可以通过归降外交加快整合，连续败战和重要城池失陷提高成功率；机制可配置，剧情保留选择空间。

本文保留原始需求规格；本轮已实现的接口、条款范围与验证见 [完整实现记录](AI_CAMPAIGN_IMPLEMENTATION.md)。[参数与分支示例](examples/ai-campaign-rules.example.json) 使用实际运行字段，样稿文件不自动加载。正文中赔粮、换俘、正式官爵等是扩展方向，并非本轮可选条款；已实现的是金钱、相邻割地、保留任官、家产保障、自治与贡赋。已完成多种子半年和全剧本短期模拟，仍不等同多年平衡验证。

## 1. 分离规则、倾向和剧情

三层共用同一命令入口，不让剧情直接写城市归属。

1. **规则层**：评估军事压力、提出条件、确认接受、接收财产与任命。玩家、普通规则 AI、外部 AI 共用。
2. **倾向层**：配置历史目标、扩张意愿、自治偏好和归降条件。只影响合法候选的评分。
3. **剧情层**：条件满足后向战略计划提交候选意图，如集中主攻、寻求援助、提出附庸、谈判归降。效果必须经过规则层；没有合法目标时跳过或改选。

人物姓名、势力 ID、年份和城名不写进通用归降公式。剧本可以引用既有 ID 作目标偏好，但该势力不存在、人物未出场或据点易主后不能报错或继续强行执行。

## 2. 外交命令与谈判结果

| 命令 | 发起者 | 结果范围 |
| --- | --- | --- |
| 劝降（沿用 `demand_surrender`） | 希望接收对方者 | 整体归降、要求保官／自治、转为附庸提案、拒绝 |
| 请求归降（新增 `offer_submission`） | 希望投靠者 | 向选定势力提出附庸或直接归降及条件 |
| 附庸（沿用 `vassalize`） | 希望建立宗属者 | 贡赋、外交权限、军事义务和自治范围的协议 |
| 商议整合（新增 `negotiate_integration`） | 宗主或附庸 | 整体并入、分阶段移交、继续自治、暂缓 |
| 求和／停战（沿用现有命令） | 任一交战方 | 无条件停战、赔偿、割地、交换俘虏等可选条款 |

“请求归降”与“劝降”的方向必须明确，禁止命令成功却把宗主／附庸写反。请求归降由接收者评估管理成本与承诺，不直接反用劝降概率。

谈判对象必须存续且具有合法外交代表；双方不能是同一势力。宗属变更需处理原宗主、条约和战争，不能绕过第三方权利形成循环附庸。

## 3. 归降意愿模型

首期采用可解释的加权模型，所有特征规范化到0—1：

`接受意愿 = clamp(基础意愿 + Σ(特征 × 权重), 下限, 上限)`

权重统一配置；不同结果（附庸、整体归降、割地）可以有不同基础意愿、权重和资格。先检查条款是否合法、是否有权承诺，再计算意愿，不能用“1%保底”绕过不可执行的协议。

整体归降还需存在合理动机：主动寻求投靠、战争压力明显、无法维持独立或可信的压倒性威胁等至少一种；具体条件以配置组合。实力接近、政局稳定且无投靠意愿的势力，应拒绝整体归降，而不是每月留一个保底概率等待被吞并。对第三方的败绩可以促成寻找保护者，但要求接收方确有保护能力或可达影响，不能让远方无关势力凭空收走领土。

| 特征 | 计算要点 | 对整体归降的方向 |
| --- | --- | --- |
| 军事劣势 | 可投入的有效军力、组织度、补给、距离；不只加总全国驻军 | 提高 |
| 近期连续败战 | 独立战役的有效败绩，按严重度和时间衰减 | 提高，重点权重 |
| 重要据点失陷 | 本方政治中心、主要郡治、仓储及交通枢纽的实际损失 | 提高，重点权重 |
| 被孤立 | 交通受限、缺少安全后路和可兑现的盟援 | 提高 |
| 战争承受力不足 | 粮源、兵源、战损、地方支持恶化 | 提高 |
| 合理待遇 | 保官、保护家产、有限自治、可兑现的封爵或俸禄 | 提高 |
| 接收者信誉 | 历次守约、安民、善待已降官员的记录 | 提高 |
| 独立意志 | 主公野心、核心集团支持和自治偏好 | 降低 |
| 可兑现援军 | 已有出兵、运输和可达路线；仅纸面同盟作用有限 | 降低 |
| 背约与暴行 | 杀降、毁约、拒付承诺等明确记录 | 降低 |
| 周边强权挤压 | 依赖与孤立共同形成的小势力生存压力 | 提高，次要权重 |

边缘势力不是一个固定名单，也不是“地图最外圈自动容易投降”。以体量、战略依赖、退路和援助判断；辽远但稳定、有险可守的势力仍可拒绝。曹操或袁绍一旦处于同样的危局，也适用同一公式。

### 3.1 怎样体现“吃了多次败仗后更容易降”

- 同一场持续野战按 `battleId` 只结算一次败绩，不能每天计一次；围城的逐日攻防也不重复计败。
- 小股袭扰失败与主力决战溃败按兵力损失占比、任务重要度区别计分；不能用反复送百人小队刷满政治压力。
- 败绩按近期窗口加权，战胜、恢复主力和夺回要地可抵消；不能数年前败三次就永远易降。
- 无交战记录的小势力可以因被包围、实力悬殊和待遇优厚接受附庸；整体归降要求更充分的压力或明确的主动意愿。
- 示例预期：一般弱势方整体归降较难；连续严重失败且重要据点失陷的孤立小势力，在待遇合理时进入约65%—90%的高接受区间。该区间是验收目标，不是按“三败”硬切换的阈值。

### 3.2 怎样确定“主要城池”

按政治中心、真实高阶任官所在地、人口与财政贡献、前线仓粮、交通连通性组合评分；先缓存本方要地排名。战争开始时记录关键据点基线，失陷后在近期窗口保留其意义，避免失去都城后改一次首都就抹除压力。夺回后相应恢复。

采用分组和上限，避免同一座城同时是都城、郡治、粮仓就计三次完整打击。失陷一县而剩余核心完整时，不能误判全势力崩溃。玩家自定义地图没有某个历史城市时仍可按现有节点评分。

## 4. 提条件比反复投骰子更重要

归降提案包含：接收方式、地方职务、部队处置、家产保障、自治期限、贡赋和可选政治待遇。

第一轮可出现：接受、反提案、拒绝。对方接受附庸却拒绝整体归降时，玩家可以选择接受自治、增加保障、继续施压或放弃。强硬要求解散全部亲军、撤换所有地方官会降低意愿；保留部分军权加快达成，但留下后续整合和反叛风险。

承诺必须有成本和权限检查。不能空口承诺无限粮饷，不能无权代表汉廷却直接发出正式官爵。可以区别“正式授予”“同意表奏”“本方幕府职位”，并将履约要求写入协议。

协议阶段：草拟 → 派使／答复等待 → 接受或反提案 → 双方确认 → 接收中 → 完成。拒绝、撤回、超时及局势改变均有独立出口。

向玩家提出归降或兼并请求必须由玩家确认，不能用 AI 随机判断替玩家交出领土。自动外交仅执行玩家明确授权的条款范围。

概率预览不消耗随机源；结算使用存档随机源并保存结果。相同提案在冷却内复用结果；新败战、要地易手或实质条款变化可产生新提案，但不是每次点按钮重新抽签。结果、反提案与事务编号持久化，读档不能重复接收资产。对较早存档回滚的全局随机机制不另行声称绝对防止。

## 5. 剧情采用可选条件图

不把剧本做成“日期到了就灭亡／分裂／归降”的线性脚本。节点描述可观察局势，边描述允许的选择与意图。

例如同一个“主力受挫”节点，可同时提供以下候选：

| 选项 | 倾向提高的条件 | 可接续的结果 |
| --- | --- | --- |
| 收拢部众、继续抵抗 | 腹地稳定、粮草充足、主公独立意志强 | 重整或再次决战 |
| 求援、结盟 | 有可达盟友、共同敌人明确 | 援军到来或援助落空 |
| 割地求和 | 想保主权、可割让地区与战场有关 | 停战或谈判失败 |
| 接受附庸 | 核心尚存但难独立支撑、宗主允许自治 | 稳定臣属或后续整合 |
| 整体归降 | 重要地区失陷、连续败战、待遇可信 | 资产接收、拒降集团另行处理 |

官渡试点可以配置曹袁主攻倾向，以及继承争端、向强方求援等候选。袁绍获胜、双方长期均势、继承稳定、刘备另辟方向都必须有可继续运行的分支。

历史倾向仅给评分加权，不改变合法性、不保证选中。节点没有合适分支时回到通用战略选择，不能停在那里等待唯一历史事件。

### 5.1 剧情作者可以调什么

- 条件：`all`、`any`、`not`；日期窗口可选，必须与存续、关系、战场等条件共同使用。
- 对象：自己、主要敌人、宗主、可达盟友、当前战区敌人、关键据点；剧本 ID 只作为可选选择器。
- 选择：基础权重、随局势增加／减少的权重、冷却、承诺成本、失败后的下一候选。
- 效果：提交一个已经注册的战略意图或外交命令；不执行任意 JavaScript，不直接改 `city.force`。
- 覆盖：通用默认 → 节奏预设 → 剧本 → 势力倾向 → 本局明确的玩家设置。模式决定是否启用历史加权。
- 运行中只支持经校验的调整；生效版本及参数快照进入存档，不随外部配置文件变化静默修改进行中战局。

评估每次使用同一份事实快照，先选一个高层意图再下命令；拒绝或无法执行后按配置转下一候选。允许返回早前节点，但需要冷却、滞回阈值和每次复核的转移上限，避免一天内反复称臣和独立。

## 6. 统一接收，保留拒绝空间

协议不能直接调用现有“最后一县失陷即删除军团”的灭亡流程。先建立接收事务，再按清单处理城市、人口、资源、官员、军队、朝廷、幕府、家族和运输。

每个集团分别判断服从：中央近臣、地方太守、独立方面、在外军团及地方大族。主公归降后大多数可随之归顺，但不保证百分之百。拒绝者可以离去、投奔、保持抵抗或在符合条件时形成残部势力；不得凭空新增兵粮人口。

边缘小势力的整体归降通常无需漫长治理手续，可快速进入接收；保留军权的大附庸需要持续整合。是否“快速”来自实际管理规模和协议，不来自预先写好的势力名单。

## 7. 结算频率与性能

- 战斗结束、关键城池易主时写入紧凑的战争压力记录，同时使相关缓存失效；同一事件只记一次。
- 军事事实只在需要预览、交涉或战略复核时生成；战略复核按势力错开，每月或重大事件后运行，不逐日遍历所有势力对。
- 外交答复按到期队列处理；附庸稳定性、贡赋与整合进度按月结算，不每日遍历所有势力对。
- 压力记录设置保留期限和大小上限；保留的是政治评价依据，不把完整战报再复制一份。
- 一切预览、剧情条件检查和 UI 刷新只读，不新建真实命令、不改变随机序列。

## 8. 第一轮交付边界与验收

建议先实现“统一停战与进攻授权＋战争压力记录＋劝降／附庸谈判”，随后接入整体接收；不能先把按钮改成高成功率，却仍只写入旧附庸表。

1. 固定输入下，提高真实败战压力或重要据点损失，不应降低归降意愿；援军、抵抗能力和恶劣待遇方向相反。
2. 相同军事条件下，孤立小势力比稳固强国更易接受；换势力姓名和 ID 不改变通用公式。
3. 同一持续战斗不累计多次败绩；败绩过期和恢复会降低压力，反复微小骚扰不能刷出全国归降。
4. 玩家与 AI 都能提出与回应；谈判失败后可改条件、求和、附庸或继续战争，不锁唯一分支。
5. 改一组合法配置就能改变“抵抗／求援／归降”的选择倾向，不改规则引擎；缺失目标退回通用 AI。
6. 同种子可复现；预览不改变结果；重复读档或处理同一接收事务不增发兵粮。
7. 已有地图、未登场人物、地方家族、太守及幕府引用不被剧情硬覆盖；归降同步图例与组织结构。
8. 多种子官渡观察局比较主战区聚焦、战争数量、归降占比、领土反复易手、模拟耗时，至少保留双方可能获胜和出现非历史走向的空间。

## 9. 已落地的实现接口

以下接口位于 `js/core/engine/politics.js`，由日模拟和普通命令入口调用：

- `campaignFacts(state, forceId)`：生成当前战略与谈判事实快照。
- `recordWarPressure(state, event)`：独立战役、失城和恢复的幂等记录。
- `evaluateSubmission(state, proposal)`：返回资格、意愿分项、可接受条款和反提案，只读。
- `submitDiplomaticProposal(state, proposal)`：走权限和资源验证，生成待答复协议。
- `resolvePoliticalProposals(state, events)`：按时结算并保存结果，玩家响应走显式确认。
- `beginForceReception(state, agreement, events)`：生成资产与人员接收清单，完成后再清理旧势力。
- `chooseCampaignIntent(state, forceId)`：按条件图和权重选择高层意图。

首期用白名单实现少量条件、选择器和意图，不搭建通用编程语言；扩展时增加注册项和验证。配置错误应指出文件与字段，单个剧情分支失败不能阻止其他 AI 行动。
