# 统一战争授权：第一轮实现记录

2026-10-18。对应 [AI 总体方案](AI_HISTORICAL_CAMPAIGN_PLAN.md) 的第一阶段。本文保留第一轮交付记录；后续的归降谈判、战争压力、整体接收与条件图已经接通，见 [完整实现记录](AI_CAMPAIGN_IMPLEMENTATION.md)。

## 已实现

- 每个非玩家 AI 势力持有一份 `diplomacy.warPlans[forceId]`，记录主要对手、获准主动进攻的对手和评估日。日常战术决策仍逐日运行，战略通常每30日复核；对手灭亡、达成和约以及相关边界据点易主会使旧计划提前失效，不必为调整战场空等一个月。
- 默认选一名主攻对手；规模与进取性达到配置条件时可增加次要对手。已有战争、接壤程度、敌军来袭、实力和关系参与评分，原有目标有连续性加权。
- 直辖军团、方面进取、协同出击、世界外交的自动宣战，共用中央授权判断。原有战争不会被直接删除，但非主攻方向以防卫为主，不继续任意扩大攻势。
- 途中目标易主时，按新主人检查授权；未获授权的旧围城撤围。行军进入异国城市时先检查外交状态，再触发野战，避免先打驻军后发现尚未宣战。
- 自卫与救援不需要另批新战争；已经接受的联军属于中央外交承诺，但不能突破新达成的停战保护。
- 区分停战保护与友好关系：停战不授予借道、退入友军城池或协同夹击权。玩家与 AI 间的有效停战同样受保护；已过期盟约不继续阻止行动。
- AI 议和的最短战争时间改用配置的明确天数，默认120日，兼容旧旬时间换算。后期决胜机制不能自动撕毁尚未到期的停战。
- 玩家直接发出的宣战仍是中央决策，玩家方面仍需先宣战；此轮没有新增玩家逐方面自主开战的设置窗口。正式诏令和明确的事件外交保留各自中央入口，不当成普通部将临机决策。

## 可配置项

真实运行参数位于 `game/data/common/game_rules.json` 的 `balance.ai.war_authorization`，同步进入离线镜像；不修改地图数据。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `review_days` | 30 | 中枢对手计划复核周期 |
| `max_primary_enemies` | 1 | 基础主攻对手名额 |
| `max_secondary_enemies` | 1 | 符合条件时增加的名额 |
| `secondary_min_sites` | 60 | 开辟次线的最低据点规模 |
| `secondary_min_aggression` | 1.1 | 开辟次线的最低进取性 |
| `war_bonus` / `continuity_bonus` | 80 / 25 | 已交战与延续原目标加权 |
| `border_weight` / `hostility_weight` | 4 / 0.4 | 接壤与敌意权重 |
| `opportunity_weight` / `threat_per_soldier` | 6 / 0.001 | 实力机会与来袭兵力权重 |
| `primary_target_bonus` | 40 | 直辖军团优先攻击主要对手的目标加权 |
| `min_peace_days` | 120 | 世界外交随机议和的最短战争时长 |

剧本可选 `scenario.ai_strategy.war_authorization.preferred_rivals[forceId]`，格式为 `[{"forceId":"目标ID","bonus":数值}]`。这是候选评分加权，不保证开战，不绕过停战；不存在、灭亡或不可接触的目标不会被强选。此轮没有给官渡写入固定的曹袁目标名单，也没有接入尚属设计稿的完整剧情图。

## 验证

- 新增 `tools/test-war-authorization.mjs`：主次线配置、剧本加权、计划保存、方面与协同进取、途中易主、未授权旧围城、停战先于野战、联军例外、玩家附庸保护、议和日历和非主攻方向自卫。
- `node tools/run-tests.mjs --quick`：100/100通过。
- 相关 AI、幕府、围城与持续战斗专项通过；野战专项含90日兵员合法性推演。
- 三个固定种子（20000101、23、91）分别运行官渡观察局35日，新增自动宣战分别5、4、2次；三个局面中曹操选择刘备为主要对手，袁绍选择曹操。此结果说明没有把曹操对手硬编码成袁绍，不代表已验证长期历史走向或相较旧版减少宣战的幅度。
- 三局均验证真实 `GameState.serialize` / `migrateSave` / `applySave` 保存往返，战略计划一致，地图不变，军团兵力有限且非负。
- 发现并修正既有野战测试的过时源码计数：旧断言要求三处逐回合表引用，而本轮修改前的 HEAD 已只有两处；改为分别检查战报档案与当前战场的实际渲染入口，不降低战斗数值断言。
